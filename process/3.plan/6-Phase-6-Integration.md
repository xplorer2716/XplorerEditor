| TASK-MAC-004 | macOS portability fix — hidden virtual `saveTone` (added 2026-07-29, found by the very first `macos-app-debug` run): AppleClang rejects `XpanderController.hpp` under `-Woverloaded-virtual`, an error given RQ-BLD-003's warnings-as-errors, because the 1-arg `saveTone(filename)` convenience overload hides `AbstractController`'s virtual `saveTone(filename, writer)`. Neither GCC (default flags) nor MSVC reports it, so it was latent. First resolved in `9ea06cf` with a `using midiapp::controller::AbstractController::saveTone;` declaration. **Superseded after owner design review:** the 1-arg method is not a specialisation of the inherited 2-arg virtual at all — it is a distinct Xplorer-level operation (pick the Xplorer writer, delegate, then clear the *page clipboard*, a notion that does not exist anywhere in the framework layer — verified: zero occurrences of `clipboard` under `juce/framework/`). Sharing the name was therefore the actual defect, and the `.NET` original only got away with it because C# hides by signature while C++ hides by name. Final fix: the Xplorer operation is renamed `saveXplorerTone(filename)`, so no overload set spans the inheritance boundary, the inherited `saveTone(filename, writer)` stays reachable untouched, and the `using` is no longer needed. Making it an `override` was explicitly rejected: it would push the clipboard concern into a base contract that has no clipboard and give polymorphic callers an unrequested side effect. **Status: Done — GCC `-Wall -Wextra -Woverloaded-virtual` compiles the controller clean with no `using`; a `static_cast` probe proves both `X::saveTone(string, IToneWriter&)` (inherited) and `X::saveXplorerTone(string)` still resolve, i.e. nothing is hidden; full build including `XplorerApp` succeeds and the whole suite is green (85/85, 1 environment-dependent MIDI scenario skipped).** **Acceptance Criteria:** Given the `-Woverloaded-virtual` diagnostic enabled, When `XpanderController.cpp` is compiled, Then it compiles without warning; Given the fix reverted, When it is compiled again, Then the compile fails — proving the check is not vacuous. | S | RQ-BLD-003, RQ-BLD-012; ADR-BLD-002 |
